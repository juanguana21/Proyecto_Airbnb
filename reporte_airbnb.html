Fuente de datos

Dataset de InsideAirbnb scrapeado el 15 de abril de 2026 para la ciudad de Nueva York. Incluye información de listados, hosts, reseñas, disponibilidad y precios de 35.036 propiedades distribuidas en los 5 boroughs.

Variable objetivo

Columna price originalmente en formato string con símbolo de dólar ($55.33). Se convirtió a float. El precio va desde $4.47 hasta más de $10.000 por noche, con alta asimetría positiva.

02 — Preprocesamiento

Pipeline de Limpieza

1

Eliminación de columnas vacías

Se eliminaron 12 columnas con 100% de valores nulos (neighborhood_overview, host_since, host_response_time, entre otras). El dataset pasó de 90 a 78 columnas.

2

Selección de columnas relevantes

Se seleccionaron 20 columnas con valor predictivo real: características del host (antigüedad, superhost, verificación), tipo de propiedad, ubicación, capacidad, amenities, mínimo de noches, reseñas y precio.

3

Filtrado por variable objetivo

Se eliminaron filas sin precio para evitar sesgo por imputación. Pérdida del 40.94% de registros, quedando 20.693 filas válidas. Decisión correcta: imputar el precio habría distorsionado la distribución objetivo.

4

Imputación estratégica de nulos

— bathrooms / bedrooms / beds: mediana por property_type y room_type
— review_scores_rating: 0 para listados sin reseñas (reviews = 0)
— host_is_superhost / host_identity_verified: moda (f / t)
— host_listings_count, minimum_nights, maximum_nights: mediana global

5

Ingeniería de features

— has_license: binarización (1 si tiene número de licencia, 0 si nulo)
— amenities: conteo de amenities por propiedad (capped a 40)
— Capping de maximum_nights a 365 días
— Capping de host_listings_count al percentil 95
— Reemplazo de 0 en bedrooms por 0.5 (estudios)

6

Filtrado de outliers de precio

Se acotó el precio a ≤ $800/noche para el entrenamiento, resultando en 19.953 registros. Split 70/30: 13.967 train · 5.986 test.

03 — Features

Transformación de Variables

StandardScaler

Variables numéricas continuas con distribución normal: hosts_time_as_user_years, hosts_time_as_host_years. Centrado en media 0, desviación 1.

OneHot Encoding

Variables nominales de baja cardinalidad: neighbourhood_group_cleansed (borough), room_type. Expansión a variables dummy sin multicolinealidad.

Target Encoding

Variable de alta cardinalidad: neighbourhood_cleansed (~200 barrios) y property_type (top 7 categorías). Encoding mediante category_encoders.

Funciones Personalizadas

Transformador para amenities: extrae lista JSON y retorna conteo numérico capped. Transformador binario para host_is_superhost e host_identity_verified (t/f → 1/0).

Transformación Log (Target)

La variable objetivo (price) se transformó con log1p vía TransformedTargetRegressor para reducir el efecto de outliers y mejorar la distribución.

ColumnTransformer Pipeline

Todos los transformadores se encadenaron en un Pipeline de scikit-learn para garantizar reproducibilidad y evitar data leakage entre train y test.

05 — Hallazgos

Insights del Análisis

  • Alta concentración de precios bajos: El precio más frecuente es $55.33, pero la media es $255, indicando una distribución fuertemente asimétrica hacia precios altos. La transformación logarítmica del target fue clave para mejorar el rendimiento de todos los modelos.
  • El tipo de propiedad y borough dominan la predicción: Los alojamientos en Manhattan tienen precios significativamente más altos. Los "Entire rental unit" (8.288 listings) y "Entire home/apt" representan la mayoría del dataset y tienden a precios más elevados.
  • La licencia como señal de calidad: Solo 4.511 de 20.693 listados tienen licencia activa. La binarización de esta variable captura la diferencia entre operadores formales e informales en la plataforma.
  • Superhosts verificados: mayoría del mercado: 13.613 hosts están verificados pero no son superhost, 6.107 son superhost verificados. Solo 275 hosts sin verificar, mostrando que Airbnb ha empujado fuertemente la verificación de identidad.
  • Pérdida aceptable por filtrado: Aunque se perdió el 40.94% de los datos al eliminar filas sin precio, esta decisión fue correcta. Imputar la variable objetivo habría introducido sesgo circular en el entrenamiento.
  • Limitaciones del modelo: Un R² de 0.68 indica que aún existe un 32% de varianza no explicada. Factores como la calidad de fotos, políticas de cancelación, disponibilidad estacional y demanda en tiempo real no están capturados en los datos estáticos del scraping.

07 — Siguiente iteración

Mejoras Propuestas

Optimización de hiperparámetros

Aplicar búsqueda bayesiana (Optuna) sobre Random Forest y XGBoost. Los parámetros clave a explorar son n_estimators, max_depth, min_samples_split y learning_rate.

Feature engineering avanzado

Incorporar análisis de texto de description (TF-IDF o embeddings), codificación geoespacial por cuadrantes de latitud/longitud, y features de temporada desde las fechas del scraping.

Ensemble y stacking

Combinar Random Forest + XGBoost mediante stacking con un meta-modelo lineal. Dado que ambos tienen MAE similar pero RMSE distinto, un ensemble podría reducir el error en casos extremos.
